Real measurements — not a simulation

Every point on these charts is a measured wall-clock time (median of repeated trials in C++ with std::chrono). The Big-O labels are the usual complexity classes for reference; they are not used to draw the curves — the curves come from actual runs. The benchmark pins the process to one physical CPU core (SetProcessAffinityMask on Windows / sched_setaffinity on Linux) so the OS does not migrate the thread and distort cache timing.

Built-in library + import / add your own
Default view: standard algorithms (search, sort, matrix multiply). To profile your own code with the same rigour (pinned core, fresh copies, median timing), add a function in algorithms.cpp, register it in getAlgorithms(), run ./algoscope --out my.json, then load that JSON here. You can also paste measured n and ms pairs below to compare a curve on this dashboard (browser entry is for visualization — it is not a substitute for the C++ profiler).

Affinity Proof
CPU pinning verification from run metadata
Evidence is generated by the native benchmark process and exported in JSON. Use this block to prove the run is physically pinned.
💡 Why one physical core? The scheduler can move threads between cores; each hop can flush hot caches and add noise. Pinning keeps the workload on one physical core so timings are comparable. Hyperthread siblings can still be masked depending on the implementation — check pinned_logical_cpus in the JSON meta when you run the CLI.
